# Exercise 5: Set up CI/CD pipeline with GitHub Actions for the web app

### Estimated Duration: 80 Minutes

In this exercise, you will move the codebase to a GitHub repository, create a staging environment in Azure App Service using deployment slots, and connect the two with a CI/CD pipeline built on GitHub Actions.

### Objectives

In this exercise, you will complete the following tasks:
   - Task 1: Moving the codebase to a GitHub repo
   - Task 2: Creating a staging deployment slot
   - Task 3: Setting up CI/CD with GitHub Actions
   - Task 4: Pushing code changes to staging and production
   - Task 5: Swap deployment slots to move changes in staging to production

### Task 1: Moving the codebase to a GitHub repo

In this task, you will create a GitHub repository, generate a personal access token (PAT), initialize a local Git repository, and push the source code to GitHub using PowerShell.

1. Browse to `https://github.com` in your browser and sign in to your **personal account** using your own GitHub credentials.

   > **Note:** If you don't have a GitHub account, go to `https://github.com/join` and create one before continuing.
  
2. Create a personal access token as described below.

     - In the upper-right corner of your GitHub page, select your profile photo, then click **Settings**.

        ![](media/github-01.png)

     - From the left-hand side menu, select **Developer settings**.

        ![](media/github-devset.png)

     - Now, expand the **Personal access tokens (1)** dropdown and select **Tokens (classic) (2)**. Click the **Generate new token (3)** button on the right and select **Generate new token (classic) (4)** from the list. Provide your GitHub password if prompted.

        ![](media/pat-token1-0711.png)

     - Configure the token as follows.

        - In the **Note** field, enter **Auth-token**.

        - Under **Select scopes**, select the following:

            - `repo` - Full control of private repositories

            - `workflow` - Update GitHub Action workflows

            - `write:packages` - Upload packages to GitHub Package Registry

            - `delete:packages` - Delete packages from GitHub Package Registry

            - `read:org` - Read org and team membership, read org projects

                ![The configured scopes for a GitHub Personal Access Token.](media/github-04.png "GitHub Personal Access Token Scope Configuration")

            - Leave the other values as default and select **Generate token**.

                ![](media/github-05.png)
  
3. Click the **Copy** icon to copy the token to your clipboard and save it in Notepad. Once you leave this page, the token cannot be displayed again. **DO NOT COMMIT THIS TO YOUR REPO!**

     ![The GitHub Personal Access Token. This is a secret value that should be stored somewhere safe and accessible.](media/github-06.png "Created GitHub Personal Access Token")

4. In the upper-right corner of your GitHub page, select your profile photo, click **Repositories**, and select the **New** button at the top of the repositories list. Alternatively, you can [go straight to the new repository page](https://github.com/new).

     ![GitHub.com Landing page is shown. New button to create a new repository is highlighted.](media/E5T1S4.png "GitHub new repo")


### Task 3: Setting up CI/CD with GitHub Actions

In this task, you will automate application deployment using GitHub Actions and the staging deployment slot you just created in Azure App Service.

1. Select your staging slot from the list of deployment slots.

2. From the toolbar menu, select **Download publish profile**. GitHub uses this publish profile to authenticate to Azure.

    ![The staging app service slot screen displays with the Get publish profile button highlighted on the toolbar.](media/E5T3S2-0711.png "Staging Publish Profile")

    >**Note:** Click **OK** on the **Download publish profile** pop-up, then repeat Step 2. 
    
    >**Note:** If you see the message **Basic authentication is disabled** when you try to download the publish profile, turn on basic authentication for the **staging** slot first:

    - **Basic authentication Steps:** 
    1.  In the left menu, go to Settings → Configuration → General settings tab.
    1. Set these to On:
       - SCM Basic Auth Publishing Credentials 
       - FTP Basic Auth Publishing Credentials
    1. Click Save, then Continue to confirm.
    1. Go back to Overview and click Download publish profile again.

3. Open the downloaded file in a text editor and leave it open — you will copy its contents in step 6.

4. In a web browser, return to the GitHub repository for this lab, and select the **Settings** tab.

    ![The GitHub repository web page displays with Settings highlighted in the toolbar.](media/updated83.png "GitHub Repository Settings Menu")

5. From the left menu, select **Secrets and variables (1)**. Then, click on **Actions (2)** and select **New repository secret (3)**.

    ![The Secrets item is selected in the left menu and the New repository secret button is highlighted.](media/reposecret.png "New repository secret")

6. Enter the following values in the **New secret** form, then select **Add secret**.

    | Field | Value |
    |-------|-------|
    | Name  | AZURE_WEBAPP_PUBLISH_PROFILE |
    | Secret | Paste the entire contents of the publish profile you opened in the text editor in step 3. |

    ![The New secret form displays populated with the previous values. The Add secret button is highlighted.](media/E5T3S6-0711.png "Add Publish Profile Secret")

7. Select the **Actions** tab.

    ![The GitHub repository page displays with the Actions menu item highlighted.](media/updated85.png "Actions Menu")

8. On the **Get started with GitHub Actions** screen, select the **set up a workflow yourself** link.

    ![The Get started with GitHub Actions screen displays with the set up a workflow yourself link highlighted.](media/updated86.png "Set up a workflow yourself")

9. On the workflow editor screen, set the file name to **stagingdeploy.yml**. Add the content below, then commit your changes by selecting the **Commit changes** button twice.

    ```yaml
    name: Build and deploy app

    on:
      push

    env:
      AZURE_WEBAPP_NAME: partsunlimited-web-suffix   # replace suffix
      AZURE_WEBAPP_PACKAGE_PATH: '.'
      DEPLOYMENT_SLOT: staging
      DOTNET_VERSION: '3.1'
      AZURE_RESOURCEGROUP_NAME: hands-on-lab-suffix  # replace suffix

    jobs:
      build-and-deploy:
        runs-on: windows-latest
        steps:
          # Checkout the repo
          - uses: actions/checkout@main

          # Use Node.js
          - name: Use Node.js
            uses: actions/setup-node@v3
            with:
              node-version: '10.x'

          # Setup .NET Core SDK
          - name: Setup .NET Core
            uses: actions/setup-dotnet@v1
            with:
              dotnet-version: ${{ env.DOTNET_VERSION }}

          # Run dotnet build and publish
          - name: dotnet build and publish
            run: |
              dotnet build PartsUnlimited.sln --configuration Release
              dotnet publish PartsUnlimited.sln -c Release -o PartsUnlimitedWebsite

          # Deploy to Azure Web app slot
          - name: 'Run Azure webapp deploy action using publish profile credentials'
            uses: azure/webapps-deploy@v2
            with:
              app-name: ${{ env.AZURE_WEBAPP_NAME }}
              publish-profile: ${{ secrets.AZURE_WEBAPP_PUBLISH_PROFILE }}
              package: '${{ env.AZURE_WEBAPP_PACKAGE_PATH }}/PartsUnlimitedWebsite'
              slot-name: ${{ env.DEPLOYMENT_SLOT }}
    ```

    >**Note:** The job runs on **windows-latest**, not `ubuntu-latest`. The .NET Core 3.1 SDK needs OpenSSL 1.1, which is no longer present on the Ubuntu runner image, and the build aborts with *"No usable version of libssl was found"*.

    ![The workflow editor screen displays with the file name set to stagingdeploy.yml](media/updated87.png "Workflow naming")

10. Open the Command window and run the following commands to pull the newly created `stagingdeploy.yml` file down to your local repository, so that you can edit it in the next step.

    ```cmd
    cd "C:\MCW\MCW-App-modernization-microsoft-app-modernization-v2\Hands-on lab\lab-files\src"
    ```
    ```cmd
    git pull
    ```

    ![The image shows successfully pulling down the new GitHub workflow.](media/git-pull-workflow-file-locally.png "Pull Git Workflow")

11. Open the newly pulled file `C:\MCW\MCW-App-modernization-microsoft-app-modernization-v2\Hands-on lab\lab-files\src\.github\workflows\stagingdeploy.yml` in Visual Studio Code. Replace the `suffix` placeholder on lines 7 and 11 with **<inject key="DeploymentID" />** so that the workflow targets your lab resources. Save the file by pressing **CTRL+S**.

    ![YML file is displayed with the suffix values highlighted.](media/ymlreplacesuffix.png "YML file")

12. Commit and push the change back to the `partsunlimited` GitHub repository. Execute these commands in the WebVM Command window.

    ```cmd
    cd "C:\MCW\MCW-App-modernization-microsoft-app-modernization-v2\Hands-on lab\lab-files\src"
    git add .

    ```

    ![Start Menu is open. Visual Studio Code is typed in the search box. Visual Studio Code is highlighted from the list of search results.](media/vscode-start-menu.png "Visual Studio Code")

    ![File menu is open in Visual Studio Code. Open Folder... command is highlighted.](media/vscode-open-folder.png "Open Folder")

3. Navigate to `C:\MCW\MCW-App-modernization-microsoft-app-modernization-v2\Hands-on lab\lab-files\src` and select **Select Folder (1)**.

    ![Visual Studio Code Open Folder dialog is open. The folder path is set to C:\MCW\MCW-App-modernization-stage\Hands-on lab\lab-files\src, and the Select Folder button is highlighted.](media/selectfolder.png "Select Folder")

In the Explorer window, navigate to **src (1)** > **PartsUnlimitedWebsite (2)** > **Views (3)** > **Home**, and select **Index.cshtml (4)** for editing. ### Task 5: Swap deployment slots to move changes in staging to production

Once Parts Unlimited is happy with the changes tested in staging, they can swap the two slots to promote those changes to production. In this task, you will perform that swap. Because a swap simply exchanges the two environments, it completes almost instantly and can be reversed by swapping back.

1. Go back to your lab resource group and search for `partsunlimited-web` **(1)** to find your App Service, then select the **partsunlimited-web-<inject key="DeploymentID" enableCopy="false"/>** **(2)** resource.

   ![The search box for resources is filled in with partsunlimited-web. The partsunlimited-web-20 Azure App Service is highlighted in the list of resources in the hands-on-lab-SUFFIX resource group.](media/5.5.1.png "Resources")

2. Switch to the **Deployment slots (1)** tab and select **Swap (2)**.

    ![App Service Deployment Slots tab is open. Swap button highlighted.](media/5.5.2.png "Deployment Slot Swap")

3. Select the **Start Swap** button to swap the staging slot with the production slot.

    ![Deployment Slot Swap dialog is open. Swap button is highlighted.](media/swap.png "Deployment Slot Swap")

4. Once you receive the success message, close the swap panel.

5. Visit both the production and staging slot endpoints and observe that the title change has moved to production.
