# Exercise 3: Migrate your application with App Service Migration Assistant
 
### Estimated Duration: 20 minutes

## Overview

The App Service Migration Assistant is a tool designed to assess and migrate web applications to Azure App Service. In this exercise, you will see how the tool identifies compatibility issues, provides remediation recommendations, and moves the web application onto Azure's platform-as-a-service (PaaS) offering.

## Objectives

You will be able to complete the following tasks:

- Task 1: Migrate the web application to Azure App Service

- Task 2: Configure the application connection to SQL Azure Database


## Task 1: Migrate the web application to Azure App Service

The assessment in Exercise 1 confirmed that the web application is a good candidate for Azure App Service. In this task, you will complete the migration.

1. Return to the **App Service Migration Assistant** window that you left running in the background. You can select it from the taskbar.

   ![](media/aftercode2.png)

1. Click on **Continue**.

    ![](media/m53.png)

    ![Azure Login process is complete. A message dialog is shown that indicates the login process is a success.](media/updated33.png "App Service Migration Assistant authentication approval")

## Task 2: Configure the application connection to SQL Azure Database

Now that both the application and the database are in Azure, it is time to point the application at the Azure SQL Database. In this task, you will add the database connection string to the App Service configuration.

1. In the Azure portal, navigate to your `parts` SQL Database resource by selecting the **hands-on-lab-<inject key="DeploymentID" enableCopy="false"/>** resource group and selecting the `parts` SQL Database from the list of resources.

   ![](media/sqldbslect.png)

1. Switch to the **Connection strings (1)** blade and copy the connection string under **ADO.NET (SQL authentication)** by selecting the copy button **(2)**.

   ![](media/cnctstrings.png)

1. Paste the value into a text editor, such as Notepad.exe, and replace the `{your_password}` placeholder with **<inject key="SQLVM Password" />**. Keep the completed connection string — you will need it again in Exercise 6 and Exercise 9.

    ![Notepad is open. SQL Connection string is pasted in. {your_password} placeholder is highlighted.](media/sql-connection-string-password-replace.png "Database connection string")

1. Go back to the resource list and search for `partsunlimited-web` **(1)** to find your web app and App Service plan. Select your **partsunlimited-web-<inject key="DeploymentID" enableCopy="false"/> (2)** App Service resource.

   ![](media/srchweb.png)

1. Switch to the **Environment variables (1)** blade, select **Connection strings (2)**, then click **+ Add (3)**.

    ![](media/envt.png)

1. On the **Add/Edit connection string** panel, enter the following:

   - **Name (1)**: Enter `DefaultConnectionString`
   - **Value (2)**: Enter the SQL connection string you completed in Step 3.
   - **Type (3)**: Select **SQLAzure**
   - **Deployment slot setting (4)**: Select this option so that the connection string stays with its deployment slot. This matters in the next exercise, where you add a staging slot.
   - Select **Apply (5)**.

     ![](media/addstring.png)

1. Select **Apply (1)** and **Confirm (2)** in the Save changes dialog.

   ![](media/m61.png)

1. Switch to the **Overview (1)** blade and select **Default domain (2)** to browse to the Parts Unlimited website, now running on Azure App Service and backed by Azure SQL Database.

    ![](media/dd.png)
    
1. The migrated site opens in a new tab, confirming that the application and its database are both running in Azure.

    ![](media/azweb.png)
